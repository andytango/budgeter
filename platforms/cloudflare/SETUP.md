# Cloudflare setup (agent runbook)

Deploys the app generated by `node tools/create.mjs cloudflare <APP>` as a Worker with D1, behind
Cloudflare Access (emailed one-time code). Free plan is enough. Steps marked **USER** need the human;
do everything else yourself. Placeholders: `<APP>` generated folder, `<BUDGETER>` this repo,
`<DOMAIN>` e.g. `budget.example.com`, `<EMAIL>` the allowed address(es), `$CF` =
`https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID`.

API shapes below were current when written. If a call is rejected, check the Cloudflare API reference
and adapt rather than guessing.

## 0. Prerequisites

- **A domain on Cloudflare** (a zone). Access needs a real hostname; `workers.dev` is disabled on purpose.
  If the user has none, suggest Vercel + Supabase instead.
- **Credentials.** Either `npx wrangler login` (local machine with a browser), or **USER** creates an
  API token (dashboard → My Profile → API Tokens → Create Token → Custom) with:
  - Account: Workers Scripts Edit, D1 Edit, Access: Apps and Policies Edit,
    Access: Organizations, Identity Providers, and Groups Edit
  - Zone (their domain): Workers Routes Edit, DNS Edit, Zone Read

  and gives you `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID` as environment variables (in Claude
  Code on the web: the environment's settings, not the chat).
- Check: `cd <APP> && npm install && npx wrangler whoami`.

## 1. Database

```sh
npx wrangler d1 create budgeter-db            # prints database_id
```
Put the id in `wrangler.jsonc` (`database_id`), then:
```sh
npx wrangler d1 execute budgeter-db --remote --file=schema.sql
```

## 2. Push keys

```sh
node <BUDGETER>/tools/gen-vapid.mjs > /tmp/vapid.json     # outside any repo
```
`publicKey` → `VAPID_PUBLIC_KEY` in `wrangler.jsonc`. Keep the file until step 5 (the private key goes
into a Worker secret), then delete it.

## 3. Cloudflare Access

1. Team domain:
   `curl -s -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" $CF/access/organizations` → `result.auth_domain`
   (e.g. `myteam.cloudflareaccess.com`). If this fails because Zero Trust isn't set up: **USER** opens
   the dashboard → Zero Trust, picks a team name and the Free plan. Then retry.
2. One-time PIN login: `GET $CF/access/identity_providers`; if none has `"type": "onetimepin"`,
   `POST $CF/access/identity_providers` with `{"name": "One-time PIN", "type": "onetimepin", "config": {}}`.
3. The application (only `<EMAIL>` allowed; 30-day sessions suit a phone):
   ```sh
   curl -s -X POST $CF/access/apps -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" -H "content-type: application/json" \
     -d '{"name": "Budgeter", "type": "self_hosted", "domain": "<DOMAIN>", "session_duration": "720h",
          "app_launcher_visible": false,
          "policies": [{"name": "Owner", "decision": "allow", "include": [{"email": {"email": "<EMAIL>"}}]}]}'
   ```
   One `include` entry per allowed address. Save `result.aud`.
4. In `wrangler.jsonc`: `ACCESS_TEAM_DOMAIN` = `https://<auth_domain>`, `ACCESS_AUD` = the aud.

## 4. Domain

In `wrangler.jsonc`, replace `REPLACE_ME_DOMAIN` (route pattern and `VAPID_SUBJECT`) with `<DOMAIN>`.
Leave `workers_dev` and `preview_urls` false: those addresses would bypass Access.
`grep -n REPLACE_ME wrangler.jsonc` must only show the comment on line 1.

## 5. Deploy

```sh
npx wrangler deploy                      # creates the Worker, custom domain and DNS record, and the cron
node -e 'process.stdout.write(JSON.parse(require("fs").readFileSync("/tmp/vapid.json","utf8")).privateJwk)' \
  | npx wrangler secret put VAPID_PRIVATE_JWK
rm /tmp/vapid.json
```

## 6. Load a budget

Load the demo first to check everything, then the user's real budget once it exists (AGENTS.md, phase 4):
```sh
node <BUDGETER>/tools/validate.mjs <budget.json>
node <BUDGETER>/tools/make-seed.mjs <budget.json> > /tmp/seed.sql
npx wrangler d1 execute budgeter-db --remote --file=/tmp/seed.sql && rm /tmp/seed.sql
```

## 7. Verify

- `curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' https://<DOMAIN>/api/budget` → a 302 to
  `…cloudflareaccess.com` (Access is in front). A 200 means the app is public: stop and fix.
- `npx wrangler deployments list` shows the deployment. The deploy output lists the `* * * * *`
  schedule (also in the dashboard: Workers → budgeter → Settings → Triggers).
- **USER**: open `https://<DOMAIN>` on their phone, sign in with the emailed code, see the budget.
- Push, once the user has tapped the bell (see AGENTS.md, phase 5):
  `npx wrangler d1 execute budgeter-db --remote --command "INSERT INTO notifications (title, body) VALUES ('Budget', 'Test from setup')"`,
  then a minute later `... --command "SELECT sent_at, result FROM notifications ORDER BY id DESC LIMIT 1"`
  → `result` like `201` (one status per device). `no devices` = nobody has subscribed yet.

## Day to day

- Code changes: `node <BUDGETER>/tools/create.mjs cloudflare <APP> --update`, then `npx wrangler deploy`.
- Data: written by the daily routine (see `snippets.md`); no deploy needed.
