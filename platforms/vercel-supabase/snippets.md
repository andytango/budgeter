# Vercel + Supabase: snippets for the Claude side

Paste these blocks into the user's `CLAUDE.md` and daily routine prompt (see AGENTS.md, phase 4),
with the placeholders filled in. The routine's environment needs `SUPABASE_URL` and
`SUPABASE_SECRET_KEY`, or the Supabase connector (`execute_sql`).

REST calls below use `-H "apikey: $SUPABASE_SECRET_KEY" -H "content-type: application/json"` (plus
`-H "Authorization: Bearer $SUPABASE_SECRET_KEY"` if it's a legacy JWT key). Build bodies from files
with `jq` or Node; never retype JSON.

## MEMORY (for CLAUDE.md)

```markdown
- Phone app: https://<HOST> (Vercel project `budgeter`; sign-in by emailed code via Supabase Auth; allowed: <EMAIL>).
  Code: `<APP>` (generated by Budgeter's tools/create.mjs; update with `--update`, deploy with `npx vercel deploy --prod --yes`).
- Supabase project `<REF>`: table `docs` row `current` = the budget JSON (column `body`, jsonb);
  `push_subs` = my devices; `notifications` = outgoing pushes (insert a row to notify my phone; a future
  `created_at` schedules it, e.g. `'2026-10-01 08:00 Europe/London'`). Data changes need no deploy.
- Credentials: env vars `SUPABASE_URL` / `SUPABASE_SECRET_KEY` (or the Supabase connector).
```

## READ (routine: get the budget)

```sh
curl -s "$SUPABASE_URL/rest/v1/docs?id=eq.current&select=body" -H "apikey: $SUPABASE_SECRET_KEY" | jq '.[0].body' > budget.json
```
Or `execute_sql`: `select body from docs where id = 'current'`. Edit the file.

## WRITE (routine: save the budget)

Validate first: `node <BUDGETER>/tools/validate.mjs budget.json` (fix every error; itemise any gap).

- Whole document (history included), including rollovers:
  ```sh
  jq -c '{body: .}' budget.json | curl -s -X PATCH "$SUPABASE_URL/rest/v1/docs?id=eq.current" \
    -H "apikey: $SUPABASE_SECRET_KEY" -H "content-type: application/json" --data-binary @-
  ```
- With the Supabase connector: `update docs set body = body || $j$<the document WITHOUT history>$j$::jsonb where id = 'current'`,
  and on a rollover first
  `update docs set body = jsonb_set(body, '{history}', (body->'history') || jsonb_build_array($j$<finished period>$j$::jsonb)) where id = 'current' and jsonb_array_length(body->'history') = <history count before>`.
- Check: `select body->>'asOf', jsonb_array_length(body->'history') from docs where id = 'current'`.

## NOTIFY (routine: push to the phone)

```sh
curl -s -X POST "$SUPABASE_URL/rest/v1/notifications" -H "apikey: $SUPABASE_SECRET_KEY" \
  -H "content-type: application/json" -d '{"title": "Budget", "body": "<text>"}'
```
Scheduled: add `"created_at": "2026-10-01T08:00:00+01:00"`. Sent within a minute. Check:
`GET $SUPABASE_URL/rest/v1/notifications?select=sent_at,result&order=id.desc&limit=1` (`no devices` =
notifications aren't on yet: remind the user about the bell once).
